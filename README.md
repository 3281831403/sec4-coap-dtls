网关对物联网设备只校验了会话是否已建立，重放的指令照样下发，阀门被开了两次：同一序号在时间窗内只允许执行一次，会话、对端与指令作用域必须先通过校验，过期消息必须丢弃，批量处理时各设备的状态彼此隔开。

安全契约

消息必须按序号与时间窗去重。必须校验会话与对端标识。指令必须校验作用域。同一序号不得重复执行。过期消息必须丢弃。批量处理各设备独立。

不变量

同一序号最多执行一次。未认证会话的指令永不执行。

消息字段

session 表示会话标识，peer 表示对端标识，seq 表示序号，ts 表示以秒为单位的时间戳，cmd 表示指令名称，scope 表示指令作用域。

策略字段

window 表示时间窗半径，时间窗端点包含在内。seq_modulus 表示序号回绕周期。scopes 表示作用域到允许指令集合的映射。

接口约定

parse_message 接收映射或 JSON 文本，返回规范化消息。

check_session 判断会话是否已建立。

check_peer 判断消息对端是否与当前会话一致。

check_replay 判断序号是否尚未执行。

check_window 判断消息时间是否落在以当前时间为中心的时间窗内。

check_scope 判断指令名称是否属于其作用域允许的指令集合。

handle 完成校验、执行与序号记录，并返回处理结果。

coap_batch 逐条处理消息，返回包含结果明细的汇总。
